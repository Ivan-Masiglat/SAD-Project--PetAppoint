# SAD 003 | System Analysis and Design | Group 5: PetAppoint Appointment System

Client accounts and appointment requests are stored in Firebase Authentication and Cloud Firestore. New bookings are saved in the Firestore `appointments` collection with `pending` status; they appear in the admin's pending list and on the client's homepage. Admin acceptance, cancellation, completion, and rescheduling changes are also saved to Firestore. Pet profiles remain in browser local storage, while the admin client directory uses appointment pet snapshots so pet names edited by clients appear there too.

Client sign-up creates a Firebase Authentication account and a profile document in the Firestore `clients` collection. Client login uses Firebase Authentication. Editing a pet name or species updates that pet's existing appointment snapshots so the admin dashboard, appointment list, and calendar show the latest details; admin appointment views subscribe to Firestore for live updates. Clients may only change pet details on their own appointments. The admin service catalog also uses Firestore. The web Firebase configuration is in `shared/firebase.js`. Publish the latest rules in `firestore.rules` from Firebase Console → Firestore Database → Rules. The rules allow client profile creation by its owner, client profile reads by its owner or the admin, public service reads, service creation only by the authenticated `admin@gmail.com` account, client-owned appointment creation and reads/limited pet-detail updates, and admin appointment reads and updates.

New appointments reserve their date/time in the private `appointmentSlots` collection to prevent overlapping bookings. Regular appointment start times are hourly from 9:00 AM to 8:00 PM Monday through Saturday and 9:00 AM to 5:00 PM Sunday, with noon excluded for lunch. Emergency Care searches hourly start times 24/7. A separate `appointmentAvailability` collection exposes only reserved date/time pairs so the public landing page can preview a calendar without exposing appointment or client details. Visitors can select a day and see each open or unavailable appointment time. Cancelled and completed bookings release both records. The Book Appointment button then asks users to sign in or create an account. The homepage also provides appointment history, a nearest-slot Emergency Care request, a clinic contact form that opens an email draft to `PetAppoint@vet.ph`, and a view-only service catalog. The initial PHP prices are approximate examples; an admin can change them from Admin → Services. Publish the current `firestore.rules`; have the admin load the appointments page once to backfill availability records for older active bookings.

Existing prototype accounts stored only in browser local storage are not Firebase accounts; users need to sign up again through the Firebase-connected form. Existing appointments stored only in browser local storage are not migrated to Firestore.

Because the Firebase SDK is loaded as browser modules, run the site through a local web server instead of opening HTML files directly. From the project root, run `py -m http.server 8000` and open `http://localhost:8000/landingpage/landingPage.html`.
